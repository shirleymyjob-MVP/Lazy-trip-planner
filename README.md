# ✈️ 懶人行程規劃（原型）

睇 IG／YouTube／小紅書旅遊片，又懶得逐間搜尋、自己排行程？
MVP 只收**截圖**。真實用法係：見到地方就截圖，iPhone 撳「複製並刪除」，然後貼進行程匣，唔使先儲存去相簿再揀圖。

1. **行程匣（先做）**：Cmd/Ctrl+V，或者撳「從剪貼簿貼上」。相簿可以**批量上載**多張。每批可以寫短備註，例如「只要圖中 1、4」。未填日期同偏好都收得。貼上同上傳都**唔使揀城市**
2. **即時反應**：貼完先顯示「認緊」，之後出店名，或者「認唔到」。唔會等到排行程先知道結果
3. **自動標地區**：認完會按畫面同文字標地區，例如福岡、博多、Hakata、今泉。一間店可以屬於多過一個地區（例如一蘭喺福岡同東京）。返嚟可以按地區睇行程匣。估唔準就顯示**未分類**，可以之後一撳改，可加可減，唔改都得，唔會擋貼上
4. **一齊改**：填顯示名，複製分享連結。另一個人開同一條連結可以貼相、改備註、剔選同排行程。每張卡寫明邊個第一個加入。資料放喺本機 `data/trips/`（或 `TRIP_STORE_DIR`）。冇登入，最後寫入嗰個贏
5. **開始排行程（稍後，收費動作）**：日數、偏好、同行有預設。如果剔咗嘅項目交集得一個地區，會跟嗰個地區，唔使再揀城市。撳之前要先見到**至少一個**齊名、地址、營業時間、評分嘅樣本，同預計等待。未齊就先撳「先核對一個樣本」
6. **下載**：行程 Markdown 會帶對得返嘅地址、營業時間、評分

行程匣只做快認店名。地址、營業時間、評分喺排行程之前先核對。唔會擷取 Instagram／YouTube／小紅書連結，亦唔會叫你貼店名或 Maps 連結做主要輸入。

## 收費過關

| 線 | 狀態 | 說明 |
|---|---|---|
| A. 貼上或批量上載之後即時出店名，或者「認緊／認唔到」 | **行為已做** | 畫面會先完成一次「認緊」，之後先叫快認店名。冇 API key 就即刻「認唔到」，唔會空等。真實 Gemini 店名時延**未量度** |
| B. 收費／排行程之前至少一個齊資料樣本 + 預計等待 | **行為已做** | 「開始排行程」冇樣本就撳唔到。預計秒數係預算：核對 20 秒（有未齊資料先計）+ 排日程 25 秒。**唔係**真實 Gemini 實測 |
| C. 排行程唔可以又要 1.5–3 分鐘、又冇評分 | **未過** | 評分唔齊就唔俾開始，排行程時亦會先核對未齊嘅地方。但呢個環境冇真實 API 計時，**未能證明**成個排行程少過 90 秒 |

本機量度（2026-10-24，冇呼叫 Gemini）：3024×4032 純色 JPEG 縮圖中位數 **149 ms**（20 次，p95 172 ms）。地區判斷 1000 次約 **5 ms**。一張圖寫入再讀出分享行程少過 **1 ms**。呢啲係送去模型之前嘅準備時間。

快路徑同慢路徑係分開嘅：`recognize_names` 只問店名同地區；`enrich_places` 用 `gemini-3.5-flash-lite` 同 Google Maps 補地址、營業時間、評分；`generate_itinerary` 先排日程。核對後仍然缺資料會出警告，唔會靜靜當成功。

## QA 手動步數

兩段分開計，因為收截圖同排行程可以唔同時間做。

**放入行程匣：1 步**（貼上之後）

- 桌面：Cmd/Ctrl+V，或者撳「從剪貼簿貼上」。亦可以批量上載相簿。唔使揀地區
- 貼完會見到「認緊」，之後係店名或者「認唔到」
- 備註可順手寫，唔使再撳確認
- iPhone：撳完「複製並刪除」之後，可能要先撳一下貼上框，再貼上（瀏覽器唔俾網頁背景讀剪貼簿）
- 認完自動標地區，可以多過一個。未分類或者標錯，可以之後一撳改。呢下唔計進行程匣嗰 1 步，因為唔改都得

**稍後排行程：1 步**（要先有一個齊資料樣本）

- 樣本已經齊、而且預設全選，撳「開始排行程」
- 未齊地址、營業時間或評分，要先撳「先核對一個樣本」。呢下係另一次成功 AI 動作，唔計入上面嗰 1 步
- 目的地預設日本、3 日、美食同景點、同朋友。行程匣如果交集得一個地區，今次會跟嗰個地區。想改先選，唔使打字，亦唔使儲存。只有揀「其他」先有自由文字

## 注意
- 呢個係原型：每個 browser session 有使用次數上限（重新整理會重置；正式版要登入先做到真正 per-user 限額）
- **成功**嘅快認店名、「先核對一個樣本」、開始排行程各計 1 次。排行程入面嘅核對同排日程唔另計。失敗唔計。同一輪入面幾張圖、HTTP 重試、空回覆重試、分批請求唔另計。用量係每個 browser，唔係分享連結共用
- 分享連結冇登入。任何有連結嘅人都可以改同一個行程匣。兩個視窗同時寫，後寫入嘅覆蓋先寫入嘅
- 截圖只會用嚟即時分析，你手機其他資料唔會被接觸
- 多過 3 張截圖會分批同時送去 Gemini，單次請求有逾時。部分批次失敗會先列出其餘地方
- 備註提到圖中編號，但模型未有填到編號時，唔會清空成個清單，會保留結果並提示
- 「從剪貼簿貼上」要用瀏覽器 Clipboard API。Streamlit 元件框冇 `clipboard-read` 權限時，按鈕會改叫你喺貼上框按 Cmd/Ctrl+V 或長按貼上。貼上事件本身唔使呢個權限
- 地址、營業時間、評分：排行程前先核對。模型有把握先填。未有就唔當收費前樣本，唔係叫你去 Maps 先睇到

## 部署設定（Streamlit Secrets）
| Key | 必填 | 預設 | 用途 |
|---|---|---|---|
| `GEMINI_API_KEY` | ✅ | – | Gemini API key |
| `GEMINI_MODEL` | | `gemini-3.8-flash` | 排日程用嘅模型。認店名同核對樣本固定用 `gemini-3.5-flash-lite`，唔跟呢個 secret |
| `MAX_ANALYSES_PER_SESSION` | | `10` | 每個 session 最多幾多次**成功** AI 動作 |
| `GEMINI_TIMEOUT_MS` | | `120000` | 單次 Gemini HTTP 逾時（毫秒）。設咗就會覆蓋程式預設 |
| `GEMINI_RETRY_ATTEMPTS` | | `2` | HTTP 嘗試次數（包含第一次；2 = 逾時／429／5xx 再試一次）。認店名、核對、排日程共用。認店名壞 JSON 唔會再解析第二次 |

## 本地開發
```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest
mkdir -p .streamlit && echo 'GEMINI_API_KEY = "..."' > .streamlit/secrets.toml
streamlit run app.py
python -m pytest -q tests   # 用 mock，唔使真 API key
```

## 檔案
- `app.py` — Streamlit 入口。行程匣先，排行程後。分享連結同顯示名都喺呢度
- `components/inbox_paste/index.html` — 貼上框同「從剪貼簿貼上」
- `gemini_client.py` — Gemini 呼叫。`recognize_names` 係快認店名；`enrich_places` 補地址／時間／評分；`generate_itinerary` 排日程
- `trip_core.py` — 目的地清單、地區（可多過一個）、認緊／認唔到、樣本係咪齊、預計秒數、剪貼簿解碼、圖片縮細、JSON、去重、Google Maps 連結、行程 Markdown
- `trip_store.py` — 分享行程匣嘅檔案儲存
- `tests/` — 單元測試同 AppTest。預設 `LAZY_TRIP_SYNC_RECOGNIZE=1`，等測試喺同一次執行入面等到店名
